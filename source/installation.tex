\section{Step 2: Some terms}\label{step-2-some-terms}

In this tutorial we use the \textbf{command-line interface (CLI)}. It is
an alternative to the \textbf{graphical user interface (GUI)} that you
probably know better. Both let you work with your computer, but in
different ways:

\begin{itemize}
\tightlist
\item
  In a GUI, you click on buttons, open folders and use menus.
\item
  In the CLI, you type text to give \textbf{commands} (instructions to
  the computer), and you see the result as text.
\end{itemize}

When people talk about the CLI, you will also hear the words terminal,
shell and prompt. They are related, but they are not the same:

\begin{itemize}
\tightlist
\item
  The \textbf{terminal} is the window or program in which you type
  commands. Some people call it the \textbf{console}.
\item
  The \textbf{shell} is the program that reads the commands you type in
  the terminal and tells the operating system what to do. There are
  several shells, for example \textbf{bash} and \textbf{zsh}. They use
  slightly different rules, but the basic commands are the same. This
  tutorial uses bash.
\item
  The \textbf{prompt} is the text that the shell shows when it is ready
  for your next command. It often shows your user name, the name of your
  computer and the folder you are in. It usually ends with a \texttt{\$}
  sign. For example: \texttt{user@laptop:\textasciitilde{}\$}
\end{itemize}

\section{Step 3: Install or open a
terminal}\label{step-3-install-or-open-a-terminal}

\subsection{Windows}\label{windows}

Windows does not come with a terminal that understands bash commands, so
you need to install one. I recommend option 1.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{MobaXterm} (recommended)

  \begin{itemize}
  \tightlist
  \item
    A terminal program with the most common Linux commands built in. It
    can also connect to an HPC.
  \item
    Small and easy to install. This is the best option if you are new to
    the command line.
  \item
    Follow these installation instructions:
    \href{https://hpc.ncsu.edu/Documents/mobaxterm.php}{MobaXterm
    setup}. The free Home Edition is all you need.
  \item
    The Home Edition comes in two versions: the \textbf{installer
    edition} and the \textbf{portable edition}. Both work for this
    tutorial. The portable edition does not need administrator rights,
    so choose it if you cannot install software on your computer (for
    example on a UvA computer). You unzip it and start MobaXterm from
    that folder.
  \item
    After you install it, open MobaXterm and click on \textbf{Start
    local terminal}.
  \item
    Then change two settings, see ``MobaXterm: choose a permanent
    folder'' below.
  \end{itemize}
\item
  \textbf{Windows Subsystem for Linux (WSL2)}

  \begin{itemize}
  \tightlist
  \item
    Installs a full Linux system inside Windows. We recommend Ubuntu,
    which is the default and uses bash.
  \item
    This is a heavier installation. It needs more disk space and more
    computer resources than MobaXterm.
  \item
    Choose this option if you are comfortable with installing software,
    or if you already use the command line.
  \item
    Follow the installation instructions from Microsoft:
    \href{https://learn.microsoft.com/en-us/windows/wsl/install}{Install
    WSL}.
  \item
    After you install it, open the \textbf{Ubuntu} app from the Start
    menu.
  \end{itemize}
\end{enumerate}

\subsubsection{Windows + MobaXterm: choose a permanent
folder}\label{windows-mobaxterm-choose-a-permanent-folder}

If you installed MobaXterm, please read the text below!

MobaXterm keeps two things in folders that you can choose:

\begin{itemize}
\tightlist
\item
  Your \textbf{home directory}: your personal folder in the terminal,
  which MobaXterm calls \texttt{/home/mobaxterm}. This is where you work
  during the tutorial.
\item
  The \textbf{root directory} \texttt{/}: the system part of the
  terminal. Extra programs that you install into MobaXterm (for example
  the text editor \texttt{nano}) are stored here.
\end{itemize}

Depending on the edition, MobaXterm keeps both in a temporary folder and
\textbf{deletes them when you close MobaXterm} (the portable edition
does this by default). Then all your work from day 1 would be gone on
day 2, and you would have to install extra programs again every time.

To prevent this, tell MobaXterm to use a normal folder on your computer.
This has an extra advantage: you can find all your files from the
tutorial in File Explorer.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Make a new folder.} Open File Explorer and go to \textbf{This
  PC}, then the \textbf{C: drive}, then \textbf{Users}, then the folder
  with your user name. Make a new folder there and call it
  \texttt{MobaXterm\_home}. The full path is then
  \texttt{C:\textbackslash{}Users\textbackslash{}YourUserName\textbackslash{}MobaXterm\_home}.
\item
  \textbf{Tell MobaXterm to use it.} In MobaXterm, click on
  \textbf{Settings} in the top toolbar, then \textbf{Configuration}, and
  go to the \textbf{General} tab. Choose your new folder in two places:

  \begin{itemize}
  \tightlist
  \item
    Next to \textbf{Terminal home directory}, click on the yellow folder
    icon and choose \texttt{MobaXterm\_home}.
  \item
    Next to \textbf{Terminal root (/) directory}, click on the yellow
    folder icon and choose \texttt{MobaXterm\_home} as well.
  \item
    MobaXterm then shows the folders as
    \texttt{\_ProfileDir\_\textbackslash{}MobaXterm\_home} and
    \texttt{\_ProfileDir\_\textbackslash{}MobaXterm\_home\textbackslash{}slash}.
    That is fine: \texttt{\_ProfileDir\_} is MobaXterm's short name for
    \texttt{C:\textbackslash{}Users\textbackslash{}YourUserName}. (In
    older MobaXterm versions, these fields are called \textbf{Persistent
    home directory} and \textbf{Persistent root (/) directory}.)
  \end{itemize}
\item
  Click \textbf{OK}. Close MobaXterm and open it again.
\end{enumerate}

Why not the Desktop or the Documents folder? On many computers, these
folders are synced with \textbf{OneDrive}. OneDrive tries to upload
every file you make there, and sequencing data can get large. A folder
directly in your user folder is not synced.

\subsection{Mac}\label{mac}

Every Mac comes with a terminal. You do not need to install anything. To
open it, do one of these:

\begin{itemize}
\tightlist
\item
  In Finder, go to \textbf{Go}, then \textbf{Utilities}, and open
  \textbf{Terminal}.
\item
  Or press Cmd + Space to open Spotlight, type \texttt{Terminal} and
  press Return.
\end{itemize}

Newer Macs (macOS Catalina and later) use zsh as their shell, not bash.
That is fine. Almost everything in this tutorial works the same way in
zsh, and I point out the places where it is different.

\subsection{Linux}\label{linux}

Every Linux system comes with a terminal, and the shell is usually bash.
You do not need to install anything. Open the terminal from your
applications menu, or search for ``Terminal'' (depending on your system
it can also be called Konsole or xterm).

\section{Step 4: Check 1, test your
terminal}\label{step-4-check-1-test-your-terminal}

When the terminal is open, you should see a window with a prompt,
similar to the one below. Your prompt will show your own user name and
computer name, and the colors may be different.

Type the command below in your terminal and press Enter. Type it exactly
as it is shown. Capital letters matter.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Print the name of the shell you are using}
\BuiltInTok{echo} \VariableTok{$SHELL}
\end{Highlighting}
\end{Shaded}

\texttt{echo} prints text to the screen. \texttt{\$SHELL} stands for the
name of the shell you use, so together they print that name.

On my computer (WSL with Ubuntu), this prints:

\begin{verbatim}
/bin/bash
\end{verbatim}

Your output may look a bit different. What matters is that you see a
line that ends with \texttt{bash} or \texttt{zsh} (for example
\texttt{/bin/zsh} on a newer Mac). If you see this, your terminal works.

\section{Step 5: Check 2, log in to
Crunchomics}\label{step-5-check-2-log-in-to-crunchomics}

Do this check once you have the email that your Crunchomics account is
ready.

\subsection{Your network}\label{your-network}

You can only connect to Crunchomics from the UvA network:

\begin{itemize}
\tightlist
\item
  At the UvA, use the \textbf{eduroam} Wi-Fi. The open Amsterdam Science
  Park Wi-Fi does not work.
\item
  From home or anywhere else, connect to the \textbf{UvA VPN} first. If
  you have not set up the VPN, or it does not work, contact the UvA ICT
  service desk.
\end{itemize}

\subsection{Log in}\label{log-in}

To log in to Crunchomics, type the command below. Replace
\texttt{uvanetid} with your own UvAnetID, and press Enter.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Log in to Crunchomics (replace uvanetid with your own UvAnetID)}
\FunctionTok{ssh}\NormalTok{ uvanetid@omics{-}h0.science.uva.nl}
\end{Highlighting}
\end{Shaded}

What the parts mean:

\begin{itemize}
\tightlist
\item
  \texttt{ssh} (secure shell) is the command that connects your terminal
  to another computer.
\item
  \texttt{uvanetid@} tells Crunchomics who you are.
\item
  \texttt{omics-h0.science.uva.nl} is the address of the computer you
  connect to.
\end{itemize}

Two things that surprise most people the first time:

\begin{itemize}
\tightlist
\item
  The first time you connect, you may get a question that ends with
  \texttt{Are\ you\ sure\ you\ want\ to\ continue\ connecting\ (yes/no/{[}fingerprint{]})?}.
  Type \texttt{yes} and press Enter. Your computer then remembers
  Crunchomics and does not ask again.
\item
  Then you are asked for your password. Use your UvA password.
  \textbf{While you type the password, nothing appears on the screen.}
  No dots, no stars. That is normal. Type the password and press Enter.
\end{itemize}

If the login works, you see a welcome message similar to the one below,
and the prompt changes. It now shows your UvAnetID and
\texttt{omics-h0}, the name of the Crunchomics computer.

Every command you type now runs on Crunchomics, not on your laptop. For
now, log out again:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Log out of Crunchomics and return to your own laptop}
\BuiltInTok{exit}
\end{Highlighting}
\end{Shaded}

The prompt changes back to the one of your laptop. Check 2 is done.

\subsection{If the login does not
work}\label{if-the-login-does-not-work}

Check these points first:

\begin{itemize}
\tightlist
\item
  Did you get the email that your account is ready?
\item
  Did you type your UvAnetID correctly, and is there an \texttt{@}
  between your UvAnetID and the address?
\item
  Did you use the correct UvA password? Remember that nothing appears
  while you type it.
\item
  Are you on eduroam (at the UvA) or connected to the VPN (outside the
  UvA)?
\end{itemize}

The error message also gives a hint. \texttt{Permission\ denied} usually
means a wrong user name or password, or that the account is not ready
yet. If the command takes a long time and then shows
\texttt{Connection\ timed\ out}, it usually means you are not on the UvA
network.

If it still does not work, email me (see the box at the top of this
page) and copy the error message.

\section{Step 6: Choose a text editor for your
notes}\label{step-6-choose-a-text-editor-for-your-notes}

While you work through the tutorial, you keep a notebook. Each time you
run a command, you copy it into the notebook, with a short comment that
says what it does and a few words about what you saw. This is the start
of documenting your code: it lets you, and others, repeat and understand
your analysis later. We write the notebook in \textbf{Markdown}, plain
text with a few symbols for headings and code. You learn the few rules
you need on day 1.

For this you need a \textbf{plain text editor}, a program that saves
only the text you type, without any layout. Do not use Word or a similar
program. These programs change some characters, for example a straight
quote \texttt{\textquotesingle{}} into a curly quote \texttt{’}. A
command with a curly quote does not work anymore.

Pick one of these options:

\begin{itemize}
\tightlist
\item
  \textbf{RStudio} (recommended): it shows Markdown in color, and many
  of you already use it for R. Go to \textbf{File}, then \textbf{New
  File}, then \textbf{Markdown File}. This opens an empty Markdown file.
\item
  \textbf{Notepad} (Windows, already installed) or
  \href{https://notepad-plus-plus.org/}{Notepad++} (Windows, free, shows
  code in color).
\item
  \textbf{TextEdit} (Mac, already installed): first go to
  \textbf{Format}, then \textbf{Make Plain Text}, otherwise TextEdit
  saves the file with layout.
\item
  \textbf{Text Editor} or gedit (Linux, usually already installed).
\item
  \href{https://code.visualstudio.com/}{\textbf{VS Code}}: a powerful
  code editor for all systems. It takes a bit more time to set up, so I
  only recommend it if you already use it.
\end{itemize}

To check that it works, open your editor, create a new file, type a line
of text and save it as \texttt{test.md}. You can delete this file
afterwards: on day 1, we make the real notebook inside the project
folder.

\section{You are ready}\label{you-are-ready}

If both checks worked and your editor can save a \texttt{.md} file, you
are ready to start. If you join the workshop: see you on day 1!
