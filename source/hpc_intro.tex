\section{HPC introduction}\label{hpc-introduction}

On day 2, we work on \textbf{Crunchomics}, the Genomics Compute
Environment for SILS and IBED. Crunchomics is an \textbf{HPC}
(high-performance computer): a group of powerful computers that many
people share. If you work at IBED, you can get access to it as described
on the \href{installation.qmd}{Before you start} page.

Working on an HPC is a bit different from working on your own computer.
The figure below gives a simplified overview:

\begin{center}
\includegraphics[width=0.7\linewidth,height=\textheight,keepaspectratio]{../img/crunchomics1.png}
\end{center}

\begin{itemize}
\tightlist
\item
  You log in from your own computer with \texttt{ssh}, as in the check
  on the \href{installation.qmd}{Before you start} page (the left arrow
  in the figure).
\item
  When you log in, you arrive on the \textbf{login node}, also called
  the \textbf{head node}. This computer is for preparing your work, for
  example moving and editing files and writing job scripts. It is not
  for running analyses.
\item
  The analyses run on the \textbf{compute nodes}. These computers have
  many more CPUs and much more memory.

  \begin{itemize}
  \tightlist
  \item
    A \textbf{CPU} is what does the calculations, so more CPUs means
    more work can get done at the same time.
  \item
    \textbf{Memory (RAM)} is the working space a program uses while it
    runs.
  \item
    Memory is not the same as storage, which is where your files are
    kept.
  \end{itemize}
\item
  In between is \textbf{SLURM}, a \textbf{workload manager} (also called
  a \textbf{scheduler}) that is used on many large HPCs. You send your
  analysis to SLURM as a \textbf{job}, and SLURM runs it on a compute
  node. In the figure, this is the arrow ``Submit to queue''.
  \texttt{sbatch} and \texttt{srun} are the two commands that send a job
  to SLURM. We use both on the next page. SLURM does three things:

  \begin{itemize}
  \tightlist
  \item
    It gives users access to CPUs and memory on the compute nodes, for a
    limited time
  \item
    It starts and runs the jobs, and lets you check on them
  \item
    It manages the \textbf{queue}: the list of jobs that wait until
    enough CPUs and memory are free
  \end{itemize}
\end{itemize}

\begin{tcolorbox}[enhanced jigsaw, titlerule=0mm, left=2mm, breakable, leftrule=.75mm, colback=white, toptitle=1mm, colframe=quarto-callout-important-color-frame, bottomrule=.15mm, bottomtitle=1mm, opacitybacktitle=0.6, arc=.35mm, rightrule=.15mm, colbacktitle=quarto-callout-important-color!10!white, toprule=.15mm, opacityback=0, coltitle=black, title=\textcolor{quarto-callout-important-color}{\faExclamation}\hspace{0.5em}{Crunchomics etiquette}]

You share Crunchomics with many other people, so only ask for the
resources that you actually use. There are no hard limits, but please
follow these rules:

\begin{itemize}
\tightlist
\item
  Do NOT run jobs that need many CPUs or a lot of memory on the login
  node (\texttt{omics-h0}). Use the compute nodes (\texttt{omics-cn001}
  to \texttt{omics-cn005}) for this
\item
  Do NOT use more than 20\% of the CPUs or memory of the cluster for
  more than a day. If you have large jobs, contact Wim de Leeuw
\item
  Don't leave resources that you reserved unused, and set reasonable
  time limits on your jobs
\item
  Use the queue (SLURM) for large jobs. Working interactively is
  possible, but not for large jobs. We learn how to use the queue on day
  2
\item
  Close programs when you don't use them anymore, for example an R
  session
\end{itemize}

You learn how to ask for resources and time on the next page, please
look back into the etiquette rules once you run your own analyses.

\end{tcolorbox}

\section{Storage}\label{storage}

On Crunchomics, you have two folders (\texttt{\$USER} stands for your
user name):

\begin{itemize}
\tightlist
\item
  Your \textbf{home directory}, \texttt{/home/\$USER}, with 25 GB of
  space
\item
  Your \textbf{personal directory}, \texttt{/zfs/omics/personal/\$USER},
  with 500 GB of space. Since this directory is larger, you want to run
  all your analyses and install all software in this directory. On day
  2, we make a shortcut to it, \texttt{\textasciitilde{}/personal}, and
  keep our project folder there
\end{itemize}

Good to know:

\begin{itemize}
\tightlist
\item
  Your data is removed from Crunchomics when your UvAnetID expires
\item
  If you need more space, or a shared folder for a larger project with
  several team members, contact the Crunchomics team
\item
  \textbf{Snapshots:} Crunchomics automatically makes
  \textbf{snapshots}, saved copies of your files, without you having to
  do anything. It makes one every hour, which is kept for 24 hours, and
  one every day around midnight, which is kept for a week. So if you
  delete a file by mistake, you can still get it back for up to a week.
  You can look at the snapshots and read the files in them in the hidden
  \texttt{.zfs/snapshot} folder, for example with
  \texttt{ls\ /zfs/omics/personal/\$USER/.zfs/snapshot}. But snapshots
  also mean that files you delete still count towards your storage limit
  until the last snapshot with them is removed. Keep this in mind if you
  make many or large temporary files. If you need a file restored, or
  snapshots removed to free up space, contact Wim de Leeuw
\item
  Your data is stored on several disks, which protects it if one disk
  breaks. But it is not copied anywhere else. \textbf{Crunchomics is not
  a backup or an archive.} You are responsible for backing up your own
  data. The
  \href{https://ibed.uva.nl/facilities/computational-facilities/ibed-computational-support-team/ibed-computational-support-team.html}{website
  of the IBED computational support team} explains the archiving options
  at the UvA
\end{itemize}

\section{Compute resources}\label{compute-resources}

\begin{itemize}
\tightlist
\item
  Crunchomics has 5 compute nodes, each with 64 CPUs and 512 GB of
  memory
\item
  If you need more resources, or GPUs, see the
  \href{https://ibed.uva.nl/facilities/computational-facilities/ibed-computational-support-team/ibed-computational-support-team.html}{website
  of the IBED computational support team}
\item
  You find more information in the
  \href{https://crunchomics-documentation.readthedocs.io/en/latest}{Crunchomics
  documentation}
\end{itemize}
