\chapter{Introduction to Bash}\label{introduction-to-bash}

\section{\texorpdfstring{\texttt{pwd}: Find out where we
are}{pwd: Find out where we are}}\label{pwd-find-out-where-we-are}

To get started, open your terminal and get yourself oriented by typing
your first command, \texttt{pwd}, and then pressing enter:

\begin{Shaded}
\begin{Highlighting}[]
\BuiltInTok{pwd}
\end{Highlighting}
\end{Shaded}

The command \texttt{pwd} stands for \emph{print working directory}. The
\textbf{working directory} is the folder your shell is operating on
right now, so \texttt{pwd} tells you where you currently are in the file
system. You should see something like this:

\begin{verbatim}
/Users/YourUserName
\end{verbatim}

When you open a new terminal, you start in what is called your
\textbf{home directory}. This is your personal folder on the computer.

What the path to your home directory looks like depends on your system:

\begin{itemize}
\tightlist
\item
  \textbf{Mac:} \texttt{/Users/YourUserName}
\item
  \textbf{MobaXterm (Windows):} \texttt{/home/mobaxterm}
\item
  \textbf{WSL2 (Windows) and Linux:} \texttt{/home/YourUserName}
\end{itemize}

In this tutorial, we work inside the home directory. That way, the
commands are the same for everybody.

\section{\texorpdfstring{\texttt{ls}: List the contents of a
directory}{ls: List the contents of a directory}}\label{ls-list-the-contents-of-a-directory}

Now that you know where you are, let's find out what is inside that
location, i.e.~what files and folders can be found there. The command
\texttt{ls} (short for \emph{list}) shows the files and folders in your
current directory. Type the following and press enter:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}
\end{Highlighting}
\end{Shaded}

In my case this returns something like this (and this will look
different for your current directory):

The colors and formatting depend on your terminal settings, but
typically:

\begin{itemize}
\tightlist
\item
  Folders (directories) appear in one color (in my example above: green)
\item
  Files appear in another (in my example above: bold white)
\end{itemize}

If your directory contains many items, the output can quickly become
overwhelming. To make sense of it, we can use options and arguments to
control how commands behave.

\section{The structure of a command}\label{the-structure-of-a-command}

A command generally has three parts:

\begin{itemize}
\tightlist
\item
  A \textbf{command name}: the program you want to run, e.g.~\texttt{ls}
\item
  An \textbf{option} (or \textbf{flag}): a way to change how the command
  behaves, e.g.~\texttt{-l} (long format). Options usually start with a
  \texttt{-}
\item
  An \textbf{argument}: the input the command works on, e.g.~a file or
  folder. Some commands work without an argument
\end{itemize}

Try the following command in your current directory to list
(\texttt{ls}) the contents of the current folder and show details in
long format (\texttt{-l})``:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

After running this, we see our files and folders again but as a more
detailed list. In the example below you can now see additional
information about who is allowed to read and change the files (the
access modes), who owns them, how large the files are, when they were
last modified and of course their name:

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: Using ls in practice}, coltitle=black, breakable, toprule=.15mm]

Throughout this tutorial, you'll notice that we use \texttt{ls} a lot.
There is a reason for that.

When working with data, sanity checks are essential, because it is easy
to make mistakes, overwrite files, or lose track of where things are.
Simple commands like \texttt{ls}, \texttt{pwd}, \texttt{wc} or
\texttt{grep} help you check what is happening to your files at every
step of an analysis.

These habits are not just for beginners, bioinformaticians rely on them
constantly.

\end{tcolorbox}

\section{Getting help}\label{getting-help}

At some point, you'll want to know what options a command has or how it
works. In this case, first check if a \textbf{manual page} (or \emph{man
page}) is available for the command by typing \texttt{man} followed by
the command name:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{man}\NormalTok{ ls}
\end{Highlighting}
\end{Shaded}

This opens the manual entry for the command \texttt{ls}. You can move
through it using:

\begin{itemize}
\tightlist
\item
  the ↑ / ↓ arrow keys, or the space bar to move down one page
\item
  \texttt{b} to move back up one page
\item
  \texttt{q} to quit the manual
\end{itemize}

Not all programs come with such a manual. Depending on the program,
there are a few common ways to get help that you can try:

\begin{itemize}
\tightlist
\item
  \texttt{man\ ls}
\item
  \texttt{ls\ -\/-help}
\item
  \texttt{ls\ -h}
\end{itemize}

\section{\texorpdfstring{\texttt{cd}: Move around
folders}{cd: Move around folders}}\label{cd-move-around-folders}

Now that we have our own project folder, let's learn how to move around
the file system with \texttt{cd} (short for \emph{change directory}).

The file system is structured like a tree that starts from a single
\textbf{root} directory, written as a forward slash (\texttt{/}). All
other folders branch out from this root directory. For example, we can
go from the root directory to the users folder, and from there into the
john folder: \texttt{/users/john}.

The location of a file or folder is written as a \textbf{path}: the
folder names along the way, separated by \texttt{/}. There are two ways
to write a path, for example to the portfolio folder:

\begin{itemize}
\tightlist
\item
  An \textbf{absolute path} starts from the root,
  e.g.~\texttt{cd\ /users/john/portfolio}
\item
  A \textbf{relative path} starts from your current location,
  e.g.~\texttt{cd\ portfolio} if you are already in \texttt{/users/john}
\end{itemize}

It is generally recommended to use relative paths from inside your
project folder. That makes your code more portable: it still works if
you move the project folder or run it on another computer.

Let's practice moving between folders. At each step, use \texttt{pwd} if
you feel that you get lost:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Move into the data\_analysis folder}
\BuiltInTok{cd}\NormalTok{ data\_analysis}

\CommentTok{\# Check where you are}
\BuiltInTok{pwd}
\end{Highlighting}
\end{Shaded}

You now should see something like
\texttt{/Users/YourUserName/data\_analysis}. You can use \texttt{cd} in
multiple ways to move around:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Move into the data folder}
\BuiltInTok{cd}\NormalTok{ data}

\CommentTok{\# Move one level up (..), i.e. go back to the data\_analysis folder}
\BuiltInTok{cd}\NormalTok{ ..}

\CommentTok{\# Quickly go back home (you now should be in the home directory)}
\BuiltInTok{cd}\NormalTok{ \textasciitilde{}}

\CommentTok{\# Move multiple levels down at once}
\BuiltInTok{cd}\NormalTok{ data\_analysis/data}

\CommentTok{\# Move two levels up, i.e. back into the home directory}
\BuiltInTok{cd}\NormalTok{ ../..}

\CommentTok{\# And go back to the data\_analysis folder}
\BuiltInTok{cd}\NormalTok{ data\_analysis}
\end{Highlighting}
\end{Shaded}

In the code above, the tilde symbol (\texttt{\textasciitilde{}}) is a
shortcut for your home directory. It is the same as typing the full
absolute path to your home (e.g.~\texttt{cd\ /Users/YourUserName}), but
much faster to type. Two dots (\texttt{..}) always mean ``the folder one
level up''.

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: Command-line completion}, coltitle=black, breakable, toprule=.15mm]

Here are some tips for faster navigation (and fewer typos):

\begin{itemize}
\tightlist
\item
  Use the Tab key for autocompletion: type the first few letters of a
  folder or file name and press Tab. For example, go to your home
  directory, type \texttt{cd\ data\_} and press Tab. The shell fills in
  \texttt{data\_analysis} for you.
\item
  If there is more than one match, the shell can not decide which one
  you mean. Press Tab twice to see all options.
\item
  Use the ↑ / ↓ arrow keys to scroll through commands you ran before.
  This is useful to rerun a command or to change a small part of it.
\end{itemize}

From now on, try to use the Tab key often, so that you do not have to
type everything yourself.

\end{tcolorbox}

\texttt{cp} (short for \emph{copy}) duplicates files or folders. When

track of them (useful folders are, for example, \texttt{data},
\texttt{scripts} and \texttt{results}). To keep our project folder
organized, let's copy the \texttt{seq\_project.tar.gz} file we just

\end{Highlighting}
\end{Shaded}

When running the two \texttt{ls} commands, we see that we now have two

directory and the other one is in our data folder. Copying large amounts
of data is not ideal, since it uses unnecessary space. However, we can
use another command to move the file into our data folder instead.

\section{\texorpdfstring{\texttt{mv}: Moving (and renaming)
data}{mv: Moving (and renaming) data}}\label{mv-moving-and-renaming-data}

\texttt{mv} (short for \emph{move}) moves files or folders to a new
location without creating a second copy:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Move the tar.gz file into the data folder}
\FunctionTok{mv}\NormalTok{ seq\_project.tar.gz data/}

\CommentTok{\# Check what happened}
\FunctionTok{ls} \AttributeTok{{-}l}
\FunctionTok{ls} \AttributeTok{{-}l}\NormalTok{ data}
\end{Highlighting}
\end{Shaded}

Notice that \texttt{mv} moved the file and, \textbf{without asking},
overwrote the copy that we had put into the data folder with
\texttt{cp}. So whenever you use \texttt{mv}, make sure that you do not
overwrite files by mistake.

\texttt{mv} is also the command to rename a file: you ``move'' it to a
new name, e.g.~\texttt{mv\ old\_name.txt\ new\_name.txt}.

\textbf{Mac users:} if you use \texttt{curl} instead of \texttt{wget},

\begin{Shaded}

\section{Wildcards}\label{wildcards}

After we have explored the folder with our sequencing data with
\texttt{ls}, we have seen that \texttt{data/seq\_project} contains 4
folders, 2 folders for two different users who each generated two
samples.

You also might have noticed that it gets tedious to figure out how many
files are in each folder, because we would need to run \texttt{ls} on
each single folder and view its contents one by one. Typing every file
name by hand also gets tedious, and you risk typos.

Luckily, the shell provides special characters to work with groups of
files using pattern matching. These characters are called
\textbf{wildcards}. The most useful wildcard is \texttt{*}, which stands
for ``any characters, any number of times (also zero times)''. For
example, \texttt{*.txt} matches all files that end with \texttt{.txt}.

We can use \texttt{*} to list all files in the \texttt{seq\_project}
folder as follows:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}
\end{Highlighting}
\end{Shaded}

\includegraphics[width=2.91667in,height=\textheight,keepaspectratio]{../img/wildcards_0.png}

You should have seen before that the sequencing files all end with
\texttt{.fastq.gz}. With this, we can make the command a bit more
specific and at the same time make the output more readable.
\texttt{*/*.gz} means ``inside any folder, any file that ends with
\texttt{.gz}'':

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}
\end{Highlighting}
\end{Shaded}

\includegraphics[width=6.25in,height=\textheight,keepaspectratio]{../img/wildcards_1.png}

Now we can easily see for each folder how many files we have.

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-color}{\faInfo}\hspace{0.5em}{Exercise}, coltitle=black, breakable, toprule=.15mm]

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Use a wildcard to list files for barcode001 only
\item
  Use a wildcard to only list R1 (i.e.~forward) files
\item
  Use a wildcard to copy all R1 files into a new folder, call this new
  folder \texttt{R1\_files}. Use \texttt{ls} to confirm if you copied
  the right files
\item
  To avoid duplicates, remove the R1\_files folder from question 3 after
  you have ensured the command you used worked
\end{enumerate}

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: More wildcards}, coltitle=black, breakable, toprule=.15mm]

\texttt{*} is not the only wildcard we can use and a full list can be
found
\href{https://tldp.org/LDP/GNU-Linux-Tools-Summary/html/x11655.htm}{here}.

Different wildcards can be useful in different contexts, not only only
when listing files but also finding patterns in files. To make such
searches as specific as possible there are different wildcards
available. A few examples are:

The {[}0-9{]} wildcard = matches any number exactly once and allows us
to extract a range of files.

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/barcode00}\PreprocessorTok{[}\SpecialStringTok{0}\PreprocessorTok{{-}}\SpecialStringTok{9}\PreprocessorTok{]*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}
\end{Highlighting}
\end{Shaded}

The {[}012{]} wildcard = matches 1 or 2 exactly once and allows us to
extract a range of files.

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/barcode00}\PreprocessorTok{[}\SpecialStringTok{12}\PreprocessorTok{]*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}
\end{Highlighting}
\end{Shaded}

{[}A-Z{]} matches any letter in capitals occurring once

{[}a-z{]}* matches any letter in non-capital letters occurring many
times

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/barcode001\_User1\_ITS\_1\_}\PreprocessorTok{[}\SpecialStringTok{A}\PreprocessorTok{{-}}\SpecialStringTok{Z}\PreprocessorTok{]}\NormalTok{001/}\PreprocessorTok{*}\NormalTok{.gz}
\end{Highlighting}
\end{Shaded}

\end{tcolorbox}

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: Finding files with find}, coltitle=black, breakable, toprule=.15mm]

With \texttt{*/*.gz}, \texttt{ls} only looks exactly one folder deep
inside \texttt{seq\_project}. If you don't know how deep your files are
stored, you can use \texttt{find} instead. \texttt{find} searches a
folder and all the folders inside it, at any depth:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Search data/seq\_project and all its subfolders for files ending in .gz}
\FunctionTok{find}\NormalTok{ data/seq\_project }\AttributeTok{{-}name} \StringTok{"*.gz"}
\end{Highlighting}
\end{Shaded}

\begin{itemize}
\tightlist
\item
  \texttt{data/seq\_project} is the folder where \texttt{find} starts
  searching
\item
  \texttt{-name\ "*.gz"} tells \texttt{find} to only print files whose
  name ends with \texttt{.gz}
\end{itemize}

We put quotes around \texttt{"*.gz"} so that the shell passes the
\texttt{*} to \texttt{find} unchanged, and \texttt{find} uses it as a
pattern while it searches.

If you want to see the full (absolute) path of each file, start the
search from your home directory with \texttt{\textasciitilde{}}:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{find}\NormalTok{ \textasciitilde{}/data\_analysis/data/seq\_project }\AttributeTok{{-}name} \StringTok{"*.gz"}
\end{Highlighting}
\end{Shaded}

Because the shell replaces \texttt{\textasciitilde{}} with the absolute
path to your home directory, \texttt{find} now prints absolute paths,
and you don't need to type your user name. This works on every system.

Note that \texttt{find} does not sort its output alphabetically like
\texttt{ls} does, so the files may appear in a different order.

\end{tcolorbox}

\section{I/O redirection to new
files}\label{io-redirection-to-new-files}

What a command prints is called its \textbf{standard output}. We have
seen that by default, commands print their standard output directly to
the terminal. For example, when we use \texttt{ls}, the list of files
and folders is printed to your terminal. However, we can also
\textbf{redirect} the standard output into a file by using the
\texttt{\textgreater{}} character.

For example, we might want to generate a list with all fastq files and
can do this as follows:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Write the list of fastq files into a new file instead of to the screen}
\FunctionTok{ls}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*} \OperatorTok{\textgreater{}}\NormalTok{ fastq\_paths.txt}

\CommentTok{\# Check that the new file exists}
\FunctionTok{ls} \AttributeTok{{-}l}\NormalTok{ fastq\_paths.txt}
\end{Highlighting}
\end{Shaded}

Here:

\begin{itemize}
\tightlist
\item
  \texttt{ls\ data/seq\_project/*/*} lists all files in the folders
  inside \texttt{seq\_project}
\item
  \texttt{\textgreater{}} tells the shell to write this list into a new
  file called \texttt{fastq\_paths.txt}, instead of printing it to the
  screen
\end{itemize}

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-important-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-important-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-important-color}{\faExclamation}\hspace{0.5em}{Important: Be careful with \textgreater{}}, coltitle=black, breakable, toprule=.15mm]

The \texttt{\textgreater{}} operator overwrites files \textbf{without
asking}. If a file with the same name already exists, its content is
replaced.

If you want to add (append) to the end of an existing file instead of
replacing it, use \texttt{\textgreater{}\textgreater{}}.

\end{tcolorbox}

\section{Exploring the content of text
files}\label{exploring-the-content-of-text-files}

Next, let's view the content of the list we just generated. Viewing the
actual files we work with is often important to ensure the integrity of

We could of course easily count this ourselves, however, if we work with

One down-side of this approach is that to be able to count the number of
files, we first need to generate a file in which we count the number of
files. This (i) can create files we do not actually need and (ii) we use
two commands while ideally we want to get the information with a single
command. Pipes, are a way around this problem.

\section{Pipes}\label{pipes}

So far, we've run one command at a time. But often, you want to combine
commands so that the output of one command becomes the input of the next
one. That's what the \textbf{pipe} (\texttt{\textbar{}}) does. It allows
us to chain simple commands together to do more complex things.

Let's use \texttt{ls} to list all fastq files and then pipe the output
from \texttt{ls} into the \texttt{wc} command, to count how many files
we work with:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{ls}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

Here:

\begin{itemize}
\tightlist
\item
  \texttt{ls\ data/seq\_project/*/*} lists all files in the folders
  inside \texttt{seq\_project}
\item
  The pipe (\texttt{\textbar{}}) sends this list directly to the next
  command, instead of printing it to the screen
\item
  \texttt{wc\ -l} counts the lines in this list, i.e.~the number of
  files
\end{itemize}

We should see again that we work with 8 files, but now we did not have
to generate an intermediate text file and have a more condensed command.

\section{\texorpdfstring{\texttt{cut}: Extract elements from

Remember, how we stored a list of sequencing files and the path leading
to these files (relative to our home directory in a text file called
\texttt{fastq\_paths.txt})?

Imagine that we only wanted to have a list of files but not the path,
how would we do that?

There are different ways to do this, the simplest one is to use
\texttt{cd} and go into the folder with our sequence files and generate
a list in there.

However, another way in which we do not have move around (and learn some

separated field.

\CommentTok{\#do the same as above but this time save the output in a new file}
\FunctionTok{cut} \AttributeTok{{-}f4} \AttributeTok{{-}d} \StringTok{"/"}\NormalTok{ fastq\_paths.txt }\OperatorTok{\textgreater{}}\NormalTok{ fastq\_files.txt}
\end{Highlighting}
\end{Shaded}

\FunctionTok{head}\NormalTok{ data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R1.fastq}

\section{\texorpdfstring{\texttt{wc}: Count things
II}{wc: Count things II}}\label{wc-count-things-ii}

We have seen before that \texttt{wc} is a command that allows us to
count the number of lines in a file and we can easily use it on fastq
files to get an idea about how many sequences we work with:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{zcat}\NormalTok{ data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R2.fastq.gz }\KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

After running this we see that we work with 179,384 / 4 sequences. We
need to divide the number we see on the screen by 4 since each sequence
is represented by 4 lines of information in our fastq file.

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Advanced tip: Better counting}, coltitle=black, breakable, toprule=.15mm]

We have seen that we need to divide the output of \texttt{wc} by four to
get the total number of sequences. We can do this with a calculator but
actually, some intermediate bash can also be used to do this for us:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{zcat}\NormalTok{ data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R2.fastq.gz }\KeywordTok{|} \BuiltInTok{echo} \VariableTok{$((} \VariableTok{$(}\FunctionTok{wc} \AttributeTok{{-}l}\VariableTok{)} \OperatorTok{/}\DecValTok{4}\VariableTok{))}
\end{Highlighting}
\end{Shaded}

In the command above we have some new syntax:

\begin{itemize}
\tightlist
\item
  The \texttt{echo} command is used to display messages or print
  information to the terminal. In our case it will print whatever is
  going on in this section \texttt{\$((\ \$(wc\ -l)\ /4))}
\item
  \texttt{\$(...)} indicates a command substitution. It allows the
  output of the enclosed command (wc -l) to be used as part of another
  command. Without command substitution (wc -l alone), you would not
  capture the output; instead, you would only see the literal text ``wc
  -l''.
\item
  \texttt{\$((...))}: This is an arithmetic expansion in Bash. It allows
  you to perform arithmetic operations inside the brackets and
  substitute the result into the command line. In this case, it
  calculates the result of dividing the number of lines in the fastq
  file by 4.
\item
  \texttt{/4}: This is dividing the result obtained from wc -l by 4.
  Since each sequence in a FASTQ file is represented by four lines
  (identifier, sequence, separator, and quality scores), dividing the
  total number of lines by 4 gives the number of sequences.
\end{itemize}

\end{tcolorbox}

\section{\texorpdfstring{\texttt{echo} and variables: Storing
information}{echo and variables: Storing information}}\label{echo-and-variables-storing-information}

Before we learn how we can use the command line to automate repetitive
tasks, we need two small building blocks.

The first one is \texttt{echo}. It prints the text you give it to the
screen:

\begin{Shaded}
\begin{Highlighting}[]
\BuiltInTok{echo} \StringTok{"Hello"}
\end{Highlighting}
\end{Shaded}

The second one is a variable. A \textbf{variable} is a name that stores
a value, for example a word, a number or a file path. You create a
variable by writing its name, an equals sign and the value:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Store the path to one sequencing file in a variable called fastq\_file}
\VariableTok{fastq\_file}\OperatorTok{=}\NormalTok{data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R1.fastq.gz}
\end{Highlighting}
\end{Shaded}

This prints nothing, however Bash will remember the value. To use the
value, put a \texttt{\$} in front of the variable name. Bash then
replaces \texttt{\$fastq\_file} with the path we stored:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Print the value stored in the variable}
\BuiltInTok{echo} \VariableTok{$fastq\_file}

\CommentTok{\# Use the variable in a command, exactly like you would use the path itself}
\FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

The second command gives the same result as typing out the full path. On
its own, that does not save us much work. Variables become really useful
when their value changes, and that is exactly what a for-loop does for
us in the next section.

A few rules for variables:

\begin{itemize}
\tightlist
\item
  The name can contain letters, numbers and underscores (\texttt{\_}),
  but no spaces. Choose a name that tells you what is stored in it,
  \texttt{fastq\_file} is easier to understand a year later than
  \texttt{x}.
\item
  A variable only exists in the terminal window where you made it. If
  you close the terminal, it is gone.
\end{itemize}

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-important-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-important-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-important-color}{\faExclamation}\hspace{0.5em}{Important: No spaces around =}, coltitle=black, breakable, toprule=.15mm]

Write \texttt{fastq\_file=data/...} without spaces around the
\texttt{=}. If you add spaces (\texttt{fastq\_file\ =\ data/...}), bash
thinks that \texttt{fastq\_file} is the name of a command, and you get
an error that ends with \texttt{fastq\_file:\ command\ not\ found}.

\end{tcolorbox}

\section{For-loops}\label{for-loops}

Imagine we want to count the lines not only in one, but in all files.
Could we do something like the code below?

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{zcat}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz }\KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

When running this, we see that the command prints a single number, 869
944, but not the counts for each individual file, so something did not
work right.

The problem with this command is that it prints the text from all 8
fastq files and only afterwards counts the lines. We basically combined
all files and then counted the lines of all 8 files together. However,
what we want is to repeat the steps below, individually for each file:

\begin{itemize}
\tightlist
\item
  Decompress a first file
\item
  Count the lines in the first file
\item
  Decompress a second file
\item
  Count the lines in the second file
\item
  \ldots{}
\end{itemize}

A \textbf{for-loop} repeats one or more commands, once for each item in
a list. Each round of the loop is called an \textbf{iteration}.

\subsection{Step 1: Check what the loop works
on}\label{step-1-check-what-the-loop-works-on}

Let's write a first loop that does not change anything yet. It only
prints the names of our sequencing files:

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \BuiltInTok{echo} \VariableTok{$fastq\_file}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

This prints the paths of all 8 fastq files, one per line. Let's go
through the parts of the loop:

\begin{itemize}
\tightlist
\item
  \texttt{for\ fastq\_file\ in\ data/seq\_project/*/*.fastq.gz;\ do}:
  this line says what to repeat over. The wildcard gives the list, here
  all 8 fastq files. In each iteration, bash stores the next file from
  the list in the variable \texttt{fastq\_file}. You choose the name of
  this variable yourself.
\item
  \texttt{echo\ \$fastq\_file}: the command we want to repeat, written
  between \texttt{do} and \texttt{done}. Here, we print the value of the
  variable. We indent this line with 4 spaces. Bash does not need this,
  but it makes the loop easier to read.
\item
  \texttt{done}: marks the end of the loop.
\end{itemize}

In other words, the loop does the same as typing these commands one
after the other:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# You don\textquotesingle{}t need to run this, it only shows what the loop does for us}
\VariableTok{fastq\_file}\OperatorTok{=}\NormalTok{data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R1.fastq.gz}
\BuiltInTok{echo} \VariableTok{$fastq\_file}
\VariableTok{fastq\_file}\OperatorTok{=}\NormalTok{data/seq\_project/barcode001\_User1\_ITS\_1\_L001/Sample{-}DUMMY1\_R2.fastq.gz}
\BuiltInTok{echo} \VariableTok{$fastq\_file}
\CommentTok{\# ... and so on, for the other 6 files}
\end{Highlighting}
\end{Shaded}

Starting a loop with \texttt{echo} is a good habit. This is called a
\textbf{dry run}: the loop shows what it would work on, without changing
anything. Before you add the real command, check the list. Do you see
all 8 files, and only the files you expect?

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: Typing a loop in the terminal}, coltitle=black, breakable, toprule=.15mm]

When you press Enter after writing the first line of the loop, nothing
runs yet. Instead, the prompt changes to \texttt{\textgreater{}}. This
means bash waits for the rest of the loop. It only starts once you type
\texttt{done} and press Enter. (On a Mac with zsh, this prompt may look
slightly different, for example \texttt{for\textgreater{}}.)

If you get stuck in this \texttt{\textgreater{}} prompt, for example
because of a typo, press \texttt{Ctrl+C} to cancel and start again.

\end{tcolorbox}

\subsection{Step 2: Add the real
command}\label{step-2-add-the-real-command}

Now that we know the loop works on the right files, we replace
\texttt{echo} with the command we actually want to run:

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

Now we get 8 numbers, one per file.
\texttt{zcat\ \$fastq\_file\ \textbar{}\ wc\ -l} is the same command as
in the variables section. The only difference is that bash now runs it 8
times, each time with a different file stored in \texttt{fastq\_file}.

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Tip: Loops written on one line}, coltitle=black, breakable, toprule=.15mm]

You might also see loops written on a single line, with \texttt{;} where
we start a new line:

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do} \FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}\KeywordTok{;} \ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

This does exactly the same as the loop above. For anything longer than
one short command, the version over several lines is easier to read.

\end{tcolorbox}

\section{\texorpdfstring{\texttt{\textgreater{}\textgreater{}}:
Collecting the loop output in one
file}{\textgreater\textgreater: Collecting the loop output in one file}}\label{collecting-the-loop-output-in-one-file}

So far, the counts only appear on the screen. We cannot see which number
belongs to which file, and the numbers are gone once we close the
terminal. Let's write the file names and the counts into a file instead.

In the section on I/O redirection, we have seen that
\texttt{\textgreater{}} replaces the content of a file, and that
\texttt{\textgreater{}\textgreater{}} adds (\textbf{appends}) text to
the end of a file. Inside a loop, this difference matters. With
\texttt{\textgreater{}}, each iteration would replace what the iteration
before it wrote, and only the result for the last file would be left. So
inside the loop we use \texttt{\textgreater{}\textgreater{}}:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Make a folder for the counts inside results}
\FunctionTok{mkdir} \AttributeTok{{-}p}\NormalTok{ results/counts}

\CommentTok{\# Start the counts file with a first line that describes its content}
\CommentTok{\# Because we use \textgreater{} here, an existing file is emptied first, so we start fresh each time}
\BuiltInTok{echo} \StringTok{"Number of lines per fastq file"} \OperatorTok{\textgreater{}}\NormalTok{ results/counts/line\_counts.txt}

\CommentTok{\# For each fastq file, add the file name and its number of lines to the end of the file}
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \BuiltInTok{echo} \VariableTok{$fastq\_file} \OperatorTok{\textgreater{}\textgreater{}}\NormalTok{ results/counts/line\_counts.txt}
    \FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l} \OperatorTok{\textgreater{}\textgreater{}}\NormalTok{ results/counts/line\_counts.txt}
\ControlFlowTok{done}

\CommentTok{\# Check the result: we expect 1 header line + 2 lines for each of the 8 files = 17 lines}
\FunctionTok{wc} \AttributeTok{{-}l}\NormalTok{ results/counts/line\_counts.txt}
\FunctionTok{cat}\NormalTok{ results/counts/line\_counts.txt}
\end{Highlighting}
\end{Shaded}

Here:

\begin{itemize}
\tightlist
\item
  \texttt{mkdir\ -p\ results/counts}: we keep the output of each
  analysis in its own folder inside \texttt{results}
\item
  \texttt{echo\ "Number\ of\ lines\ per\ fastq\ file"\ \textgreater{}\ results/counts/line\_counts.txt}:
  before the loop starts, we write a first line that describes what is
  in the file. Such a line is called a \textbf{header}. Because we use
  \texttt{\textgreater{}} here, this also empties the file if it already
  exists from an earlier run
\item
  Inside the loop, there are now two commands. The first one adds the
  name of the file, the second one adds its number of lines. Both use
  \texttt{\textgreater{}\textgreater{}}, so each iteration adds two
  lines to the end of \texttt{line\_counts.txt}
\end{itemize}

We will use these numbers again on day 2, to check what a quality
filtering tool did to our data.

Let's get a bit more advanced to show you some powerful features of
bash. Above, the file name and its count end up on two separate lines.
Imagine that you would do this for 100 files. In this case it would be
useful to see each file name and its count on the same line. We can
achieve this with the command substitution from the
\texttt{Advanced\ tip:\ Better\ counting} in the \texttt{wc} section
above.

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \BuiltInTok{echo} \StringTok{"}\VariableTok{$fastq\_file}\StringTok{: }\VariableTok{$(}\FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}\VariableTok{)}\StringTok{"}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

\begin{itemize}
\tightlist
\item
  The echo command is used to display messages or print information to
  the terminal. In our case it will print whatever is going on here
  \texttt{"\$fastq\_file:\ \$(zcat\ \$fastq\_file\ \textbar{}\ wc\ -l)"}
\item
  \texttt{\$(...)}: These parentheses are used for command substitution.
  It means that the command
  \texttt{zcat\ \$fastq\_file\ \textbar{}\ wc\ -l} is executed, and its
  output (the line count of the uncompressed content) is substituted in
  that position.
\item
  The double quotes (``\,``) perform what is called a string
  concatenation. It concatenates the filename (\$fastq\_file), a colon
  (:), a space, and the line count obtained from the command
  substitution. The entire string is then passed as a single argument to
  the echo command.
\end{itemize}

Almost perfect, now we only want to divide this by 4:

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \BuiltInTok{echo} \StringTok{"}\VariableTok{$fastq\_file}\StringTok{: }\VariableTok{$((} \VariableTok{$(}\FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l}\VariableTok{)} \OperatorTok{/}\DecValTok{4} \VariableTok{))}\StringTok{"}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

Notice, how we use both single brackets and double brackets?

\begin{itemize}
\tightlist
\item
  \texttt{\$((...))} in contrast to \texttt{\$(...)} is an arithmetic
  expansion in Bash. It allows you to perform arithmetic operations and
  substitute the result into the command line.
\end{itemize}

\end{tcolorbox}

\begin{tcolorbox}[enhanced jigsaw, bottomtitle=1mm, arc=.35mm, colbacktitle=quarto-callout-tip-color!10!white, rightrule=.15mm, colback=white, colframe=quarto-callout-tip-color-frame, opacityback=0, left=2mm, opacitybacktitle=0.6, toptitle=1mm, leftrule=.75mm, bottomrule=.15mm, titlerule=0mm, title=\textcolor{quarto-callout-tip-color}{\faLightbulb}\hspace{0.5em}{Advanced tip: Using bash to make sample mapping files}, coltitle=black, breakable, toprule=.15mm]

For a lot of mapping files for amplicon analyses, you need to prepare a
table that lists your files, often with the R1 and R2 files in separate
columns. How could we do this using bash?

This code is more advanced and uses a few concepts we have not talked
about but should give you an idea about the different data
transformations you can do with bash.

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}\KeywordTok{;} \ControlFlowTok{do}
    \ControlFlowTok{if} \KeywordTok{[[} \VariableTok{$file} \OtherTok{==} \PreprocessorTok{*}\NormalTok{\_R1.fastq.gz }\KeywordTok{]];} \ControlFlowTok{then}
        \VariableTok{r1\_file}\OperatorTok{=}\VariableTok{$file}
        \VariableTok{r2\_file}\OperatorTok{=}\VariableTok{$(}\BuiltInTok{echo} \VariableTok{$file} \KeywordTok{|} \FunctionTok{sed} \StringTok{\textquotesingle{}s/\_R1/\_R2/\textquotesingle{}}\VariableTok{)}
        \BuiltInTok{echo} \StringTok{"}\VariableTok{$r1\_file}\StringTok{,}\VariableTok{$r2\_file}\StringTok{"}
    \ControlFlowTok{fi}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \texttt{for\ file\ in\ data/seq\_project/*/*.gz}: We loop through all
  fastq.gz files
\item
  \texttt{if\ {[}{[}\ \$file\ ==\ *\_R1.fastq.gz\ {]}{]};\ then}: This
  line checks if the current file's name matches the pattern
  *\_R1.fastq.gz. The \texttt{{[}{[}\ ...\ {]}{]}} is a conditional
  construct in bash, and the == is used for string comparison. If the
  condition is true (i.e., the file is an R1 file), then the code inside
  the if block will be executed. The block starts with \texttt{if}and
  finishes at the \texttt{fi}.
\item
  \texttt{r1\_file=\$file}: This line involves creating a variable named
  r1\_file and assigning it the value of the current file
  \texttt{(\$file)}. A variable is a symbolic name or identifier
  associated with a value or data. It allows you to store and retrieve
  information for later use. Here, r1\_file is used to store the name of
  the current R1 file.
\item
  \texttt{r2\_file=\$(echo\ \$file\ \textbar{}\ sed\ \textquotesingle{}s/\_R1/\_R2/\textquotesingle{})}:
  This line sets the variable r2\_file by replacing \_R1 with \_R2 in
  the current file name. This is done using the sed command, which is a
  stream editor for filtering and transforming text.
\item
  \texttt{echo\ "\$r1\_file,\$r2\_file"}: This line prints the R1 and R2
  file names separated by a comma. This will be part of the output in
  the format R1,R2.
\end{enumerate}

We can do even more and add a column with the sample name with what we
have learned before:

\begin{Shaded}
\begin{Highlighting}[]
\ControlFlowTok{for}\NormalTok{ file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}\KeywordTok{;} \ControlFlowTok{do}
    \ControlFlowTok{if} \KeywordTok{[[} \VariableTok{$file} \OtherTok{==} \PreprocessorTok{*}\NormalTok{\_R1.fastq.gz }\KeywordTok{]];} \ControlFlowTok{then}
        \VariableTok{sample\_name}\OperatorTok{=}\VariableTok{$(}\BuiltInTok{echo} \VariableTok{$file} \KeywordTok{|} \FunctionTok{cut} \AttributeTok{{-}f3} \AttributeTok{{-}d} \StringTok{"/"} \VariableTok{)}
        \VariableTok{r1\_file}\OperatorTok{=}\VariableTok{$file}
        \VariableTok{r2\_file}\OperatorTok{=}\VariableTok{$(}\BuiltInTok{echo} \VariableTok{$file} \KeywordTok{|} \FunctionTok{sed} \StringTok{\textquotesingle{}s/\_R1/\_R2/\textquotesingle{}}\VariableTok{)}
        \BuiltInTok{echo} \StringTok{"}\VariableTok{$sample\_name}\StringTok{,}\VariableTok{$r1\_file}\StringTok{,}\VariableTok{$r2\_file}\StringTok{"}
    \ControlFlowTok{fi}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

You can easily combine this with some of the things we learned, such as
using \texttt{cut} to extract specific parts of the sample\_name as
well. I.e. lets assume you only want to list the index:

\begin{Shaded}

\ControlFlowTok{for}\NormalTok{ file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.gz}\KeywordTok{;} \ControlFlowTok{do}

\section{\texorpdfstring{\texttt{bash}: Running commands from a
script}{bash: Running commands from a script}}\label{bash-running-commands-from-a-script}

Our counting loop is now a few lines long, and we might want to run it
again later, for example when new data arrives. Instead of typing or
copying the loop each time, we can save it in a file. A text file that
contains commands is called a \textbf{script}. Bash scripts usually end
with \texttt{.sh}.

To keep our project folder tidy, we store scripts in their own folder:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Make a folder for scripts inside data\_analysis}
\FunctionTok{mkdir} \AttributeTok{{-}p}\NormalTok{ scripts}

\CommentTok{\# Check that the folder was created}
\FunctionTok{ls} \AttributeTok{{-}l}
\end{Highlighting}
\end{Shaded}

Next, we create the script with the text editor \texttt{nano} (see the
tip ``Editing text files with \texttt{nano}'' above):

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{nano}\NormalTok{ scripts/count\_lines.sh}
\end{Highlighting}
\end{Shaded}

\textbf{MobaXterm users:} if you see
\texttt{nano:\ command\ not\ found}, install it first with
\texttt{apt\ install\ nano}, as explained in that tip.

Type or copy the following into the editor:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\#!/bin/bash}

\CommentTok{\# Count the number of lines in each fastq file}
\CommentTok{\# Run this script from inside the data\_analysis folder}

\CommentTok{\# Make a folder for the counts and start the counts file with a header}
\FunctionTok{mkdir} \AttributeTok{{-}p}\NormalTok{ results/counts}
\BuiltInTok{echo} \StringTok{"Number of lines per fastq file"} \OperatorTok{\textgreater{}}\NormalTok{ results/counts/line\_counts\_bash.txt}

\CommentTok{\# For each fastq file, add the file name and its number of lines to the end of the file}
\ControlFlowTok{for}\NormalTok{ fastq\_file }\KeywordTok{in}\NormalTok{ data/seq\_project/}\PreprocessorTok{*}\NormalTok{/}\PreprocessorTok{*}\NormalTok{.fastq.gz}\KeywordTok{;} \ControlFlowTok{do}
    \BuiltInTok{echo} \VariableTok{$fastq\_file} \OperatorTok{\textgreater{}\textgreater{}}\NormalTok{ results/counts/line\_counts\_bash.txt}
    \FunctionTok{zcat} \VariableTok{$fastq\_file} \KeywordTok{|} \FunctionTok{wc} \AttributeTok{{-}l} \OperatorTok{\textgreater{}\textgreater{}}\NormalTok{ results/counts/line\_counts\_bash.txt}
\ControlFlowTok{done}
\end{Highlighting}
\end{Shaded}

Save and exit:

\begin{itemize}
\tightlist
\item
  Press \texttt{Ctrl+X} to exit, then \texttt{Y} to confirm that you
  want to save the file, then Enter to keep the file name
\end{itemize}

The commands are the same as in the
\texttt{\textgreater{}\textgreater{}} section. Two things are new:

\begin{itemize}
\tightlist
\item
  \texttt{\#!/bin/bash}: this first line is called the \textbf{shebang}.
  It tells the system that the script should be run with bash. Put it at
  the very top of every bash script.
\item
  The lines that start with \texttt{\#} are comments. Bash ignores them,
  but they tell you (and others) what the script does and how to use it.
\end{itemize}

Now we can run the whole script with a single command:

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Run the script with bash}
\FunctionTok{bash}\NormalTok{ scripts/count\_lines.sh}

\CommentTok{\# Check the output: we again expect 17 lines}
\FunctionTok{wc} \AttributeTok{{-}l}\NormalTok{ results/counts/line\_counts\_bash.txt}
\FunctionTok{cat}\NormalTok{ results/counts/line\_counts\_bash.txt}
\end{Highlighting}
\end{Shaded}

The script itself prints nothing to the screen, because all output goes
into \texttt{line\_counts.txt}. That is why we check the file
afterwards.

Why is this useful?

\begin{itemize}
\tightlist
\item
  You can run the same analysis again, with exactly the same commands,
  without typing mistakes.
\item
  The script documents what you did. Together with your notes file, it
  tells future you how a result was made.
\item
  On day 2, we use exactly this kind of script on the HPC. There, we add
  a few extra lines at the top that tell the HPC how many resources our
  job needs.
\end{itemize}

Notepad}, coltitle=black, breakable, toprule=.15mm]

Windows programs such as Notepad end every line with an extra invisible
character. Bash on Linux does not understand this character, and the
script fails with errors such as
\texttt{\$\textquotesingle{}\textbackslash{}r\textquotesingle{}:\ command\ not\ found}
or \texttt{syntax\ error\ near\ unexpected\ token}. Word processors such
as Word also add formatting and can change straight quotes (\texttt{"})
into curly quotes.

To avoid this, write your scripts with \texttt{nano}. If you prefer a
code editor such as VS Code, check that it saves the file with
\texttt{LF} line endings (in VS Code, you see \texttt{LF} or
\texttt{CRLF} in the bar at the bottom right, and can click it to change
it). This becomes important on day 2, where the scripts run on a Linux
computer.

\end{tcolorbox}
